# 接口测试设计详解

## 契约读取

接口生成器读取 operation、参数、请求体、响应、认证和 schema。路径级参数与操作级参数合并；`$ref` 递归展开但保留引用来源。未定义的行为不使用常识补齐，写入 notes 让人工确认。

## 请求维度

每个接口至少建立一个合法最小请求。随后按风险增加完整请求、缺少 required、空字符串、null、错误类型、错误格式、非法 enum、长度边界、数值边界、数组数量和特殊字符。路径、查询、头部和正文分别记录。

## 请求体策略

object 使用 required 字段构造最小样本，可选字段构造完整样本；array 同时考虑空数组、单项和上限；oneOf/anyOf 为每个主要分支选择代表样本；allOf 合并约束。example/default 优先于自行生成的值。

## 参数覆盖表

| 参数约束 | 合法案例 | 异常案例 |
|---|---|---|
| required | 提供参数 | 删除参数 |
| string | 合法格式 | 空、超长、格式错误 |
| number | 最小/最大内 | 前一、后一、负数 |
| enum | 每个高风险值 | 枚举外值 |
| array | 一项和典型集合 | 空、超量、错误项 |
| format | 规范格式 | 可解析但格式非法 |
| security | 有效凭证 | 缺失、过期、权限不足 |

## 响应断言

状态码必须来自 responses，或明确写“待确认”。成功响应检查 Content-Type、必返字段、类型、枚举、嵌套结构和安全字段；错误响应检查错误结构、错误码、消息、数据未产生副作用。不得因为服务常见行为而虚构未声明的错误码。

## 鉴权

每个需要认证的资源至少考虑无凭证、过期凭证、错误凭证、角色不足和资源越权。认证值使用变量，如 `${ACCESS_TOKEN}`。输出文件和报告不得保留真实 token。

## 幂等和重复

创建、支付、提交和删除接口需要考虑重复请求。验证是否产生重复资源、重复扣款或错误状态。请求 ID、幂等键和版本字段应作为测试数据记录。

## 依赖接口

创建、查询、修改和删除可以形成场景链，但只有在规范或业务材料明确关系时才自动连接。每一步捕获资源 ID、版本或业务结果；依赖失败要有独立案例。

## 网络和并发

超时检查客户端提示、重试、幂等和最终状态；连接断开检查服务端是否部分写入；并发更新检查冲突、锁、版本和最后一致性。性能案例不替代接口正确性案例。

## 自动化建议

接口自动化应使用 fixture、变量提取、显式超时、脱敏日志和业务断言。只检查状态码不足以证明接口正确；至少增加关键字段、数据副作用或后续查询断言。

## 接口审核清单

- 所有 operation 是否被扫描？
- 每个 required 参数是否有缺失案例？
- 类型、格式、enum、范围和长度是否覆盖？
- responses 中的状态码是否有映射？
- schema 必填字段和类型是否有断言？
- 鉴权、越权、幂等和重复是否适用并覆盖？
- 动态数据是否使用变量而非固定真实值？
- 失败响应是否验证数据未被错误修改？

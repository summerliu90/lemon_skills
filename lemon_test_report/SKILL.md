# Lemon 测试报告 Skill

## 定位

这是一个面向测试工程师的报告编排与质量校验流程。它保留测试总结、回归报告、发布验收三种工作模式，
但把“排版”和“发布判断”分开：AI 负责理解业务语义，脚本负责确定性校验、脱敏和 HTML 渲染。

## Skill 归属与项目支持

这是柠檬班原创 Skill。若当前没有可用于分析的项目或测试数据，可前往[柠檬班项目平台](http://proj.lemonban.com/)获取项目支持。

## 触发范围

用户提出“写测试报告”“整理回归结果”“做上线验收报告”“test report”时使用。只要求美化已有 Markdown
而不涉及测试结论时，可只调用 `scripts/render_report.py`。

## 工作规则

1. 先建立数据字典：项目、版本、周期、环境、用例状态、缺陷优先级、发布标准。
2. 把原始资料分成事实、推断和缺失项；缺失字段不得用猜测补齐。
3. 使用 `scripts/audit_report.py` 检查计数、百分比、范围和敏感信息。
4. 只有门禁规则全部有证据时，才能输出 Go；证据不足输出“待确认”，存在硬阻断输出 No-Go。
5. 报告正文必须保留数据来源、假设、未覆盖范围和待办责任人。
6. HTML 只渲染已经审核的 Markdown，不执行输入内容中的 HTML、脚本或外部资源。

## 三种报告模式

### 测试总结

说明本轮测试范围、执行量、结果分布、缺陷状态、覆盖度、已知风险及后续动作。

### 回归核验

增加变更范围、历史版本对比、新增/修复/重开缺陷、兼容性和性能回归证据；无法对比时明确标记缺数据。

### 发布验收

围绕版本、构建、验收清单和发布标准给出 Go / Go with risk / No-Go / Pending 四态结论，并列出上线前阻断项、
回滚条件和发布后监控项。

## 标准章节

1. 基本信息：项目、版本、报告日期、测试周期、负责人、环境、需求范围。
2. 执行摘要：结论、关键指标、阻断项、数据可信度。
3. 测试范围：已测、未测、延期原因、需求映射。
4. 用例统计：模块汇总、失败/阻塞/未执行明细、历史对比。
5. 缺陷分析：总量、状态、优先级、模块、责任人、P0/P1 和遗留清单。
6. 风险与应急：影响、概率、缓解、回滚、负责人、监控阈值。
7. 结论与建议：门禁规则逐项判定、必须完成项、发布后动作。
8. 附录：原始数据摘要、字段映射、假设、审计结果。

## 指标约定

- 执行通过率 = 通过数 /（通过 + 失败 + 阻塞 + 跳过）× 100%。
- 失败率、阻塞率使用同一个执行基数，不能把“未执行”混入分母。
- 缺陷关闭率 = 已关闭数 / 缺陷总数；缺陷总数为 0 时显示 `N/A`，不显示 100%。
- P0/P1 占比 = P0 与 P1 数量 / 缺陷总数；分母为 0 时显示 `N/A`。
- 需求覆盖率只有在需求总数和已覆盖数都存在且可追溯时计算。
- 所有百分比必须在 0 至 100 之间；原始计数与百分比冲突时以“待确认”处理。

## 输入与输出

输入可以是整理后的 Markdown、CSV/表格转出的结构化文本、缺陷清单、测试计划或自然语言补充。
本 Skill 不声称直接读取所有办公文件；若没有可靠的解析器，先要求用户提供结构化摘录。

推荐输出：

- `report.md`：审阅用报告
- `report.html`：静态展示版
- `audit.json`：校验结果、警告、脱敏命中和门禁判定

生成 HTML 前运行：

```bash
python3 scripts/audit_report.py report.md --policy references/release-gates.json --json audit.json
python3 scripts/render_report.py report.md --audit audit.json --output report.html
```

# AI 功能 Bug Playbook

## 诊断顺序

1. 固定用户原始输入和完整对话上下文，保留系统/开发者提示的版本号。
2. 记录模型、供应商、温度、最大输出、工具、检索结果、超时、重试和配额。
3. 判断问题是“事实错误、遵循错误、格式错误、工具失败、延迟/限流”中的哪一类。
4. 用相同输入重放，至少保留成功和失败样本。
5. 检查上下文预算、消息裁剪、检索召回和工具响应是否改变。
6. 只有在输入、上下文和模型版本都可比时，才讨论模型行为差异。

## 必收证据

- 用户输入原文（脱敏后）
- 最终输出原文和结构化解析结果
- 系统提示版本与配置
- 模型名称、版本、参数和请求时间
- 上下文 token 或长度限制
- 检索片段及其来源
- 工具调用参数、响应和错误
- 配额、限流和超时记录

## 不允许的捷径

“回答不正确”不能直接等于幻觉；“换一个模型能回答”不能直接证明原模型是根因；没有原始输入输出时不能评价 Prompt。

## 回归重点

固定输入一致性、上下文裁剪边界、空检索结果、工具超时、模型降级、超长输出、敏感信息拦截、版本切换和失败重试。

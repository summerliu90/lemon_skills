# XMind 导出详解

## 生成模型

XMind 文件使用 ZIP 容器。Lemon 的手工生成器写入 content.json、manifest.json 和 metadata.json，节点结构为根、模块、案例和属性。节点文本优先保证可读和可搜索，主题颜色和标记属于可选增强。

## 节点规则

案例标题以 case_id 开始，再接名称。动作和预期可以作为属性节点或多个子节点。长响应应按字段组拆分；敏感数据使用变量。不要把完整请求头、token 或生产响应写入节点。

## 标记

如果目标 XMind 版本支持标记，可以将 P0/P1/P2/P3 映射为颜色或星标；如果不支持，优先保留优先级文本。标记失败不能影响内容生成。

## 兼容检查

导出后验证 ZIP 可以打开、三个入口文件存在、content.json 可解析、根主题非空、案例节点数量与输入一致。不同 XMind 版本可能忽略主题属性，因此必须同时交付 Markdown 或 JSON。

## 转换路径

表格和 JSON 先转换为 canonical，再生成 XMind。不要直接用字符串拼接生成节点，否则列表字段、特殊字符和多行内容容易丢失。XMind 到表格的反向转换依赖属性标签，手工改名后需要重新审计。

## 失败处理

如果目标工具打不开文件，先运行 `format_auditor.py --format xmind`，再解压检查 JSON。若结构有效但版本不兼容，使用 XMind 原生导入或保留 JSON 源文件作为替代路径。

# Frontend Bug Playbook

## 诊断顺序

先确认页面、路由、用户角色、浏览器/设备和构建版本，再同时查看 Console、Network、资源加载、DOM 状态和截图。白屏、按钮无响应和样式异常要分别判断渲染崩溃、请求未发出、请求失败、状态未更新和 CSS/兼容性问题。

## 必收证据

- 浏览器及版本、设备、操作系统和屏幕尺寸
- 页面 URL、路由参数、用户角色
- Console 堆栈和 source map 版本
- 失败请求的 URL、方法、状态码、响应体和耗时
- 资源加载失败、缓存命中和 Service Worker 状态
- 成功浏览器与失败浏览器的对照
- 最近前端发布和 feature flag

## 关联判断

接口 200 不代表页面正确，仍需检查响应 schema、空数据、权限字段和状态管理；接口 500 也不应直接归因于前端，需确认请求是否由前端构造错误触发。

## 回归重点

主流浏览器、移动端、弱网、刷新/返回、缓存清理、权限变化、空态、异常响应、重复点击、懒加载和不同语言/时区。

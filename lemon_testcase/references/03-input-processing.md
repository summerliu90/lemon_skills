# 输入处理与路由

先识别文件格式，再判断内容语义，最后选择生成器。混合输入分别提取后合并到统一案例模型，并保留每个来源的定位。

| 输入 | 处理方式 | 重点 |
|---|---|---|
| Markdown/TXT/CSV | 表格或段落解析 | 字段映射、行号、原始文本 |
| DOCX/PDF | 文本和表格抽取 | 页码、段落、表格位置 |
| 图片/截图 | UI 素材登记，可接入 OCR | 只使用可见事实 |
| OpenAPI 2/3 | 读取 paths、参数、schema、responses、security | 参数和响应契约 |
| Postman v2/v2.1 | 遍历 folder、request、event | 请求、变量和脚本断言 |
| 在线文档摘录 | 当作已提取文本 | 保存 URL 或文档标识 |

结构化接口契约优先于自然语言描述；明确验收标准优先于推测；截图只证明视觉事实。不得凭空生成错误码、SLA、隐藏状态或权限规则。

不同来源先独立建立 source reference，再按模块、接口、页面或业务目标合并。冲突事实保留冲突并提示人工确认。

缺少可选依赖时给出安装提示；解析失败报告失败位置；无法识别的字段进入自定义字段；没有可验证事实时输出待补充清单。

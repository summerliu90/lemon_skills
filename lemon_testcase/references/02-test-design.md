# 测试设计汇总

## 设计入口

先提取业务目标、输入约束、角色、状态、依赖、输出和失败处理。每条事实保留 source reference，没有证据的规则标记待确认。

## 通用方法

- 正向：验证有效前置条件下的主路径。
- 反向：逐项破坏一个条件，验证拒绝、提示、错误响应或回滚。
- 等价类：将行为相同的输入归组并选择代表值。
- 边界值：覆盖最小、最大、临界前后、空值、超长和精度边界。
- 状态迁移：验证允许、禁止、重复、并发和恢复迁移。
- 场景法：围绕用户目标串联页面、接口和状态。
- 组合设计：只对有交互风险的组合进行风险取样。
- 风险驱动：优先覆盖权限、数据完整性、核心链路和高频操作。

## 测试域路由

| 来源 | 设计域 | 必补内容 |
|---|---|---|
| PRD、验收标准 | 功能 | 反向、边界、权限、恢复 |
| OpenAPI、Swagger、Postman | API | 参数、schema、鉴权、状态码、依赖 |
| 截图、设计稿 | UI | 布局、交互、状态、响应式、可访问性 |
| 容量方案 | 性能 | 负载模型、指标、降级、恢复 |
| 回归计划、CI | 自动化候选 | 稳定性、夹具、隔离、断言、维护成本 |

## 功能与 UI

功能覆盖主流程、有效/无效输入、空值、边界、权限、重复提交、依赖失败和可观察结果。UI 覆盖布局、点击、键盘、加载、空、错误、禁用、权限和响应式状态。

## 优先级

P0 是生命线、越权和核心阻断；P1 是高频主流程和重要异常；P2 是一般业务分支；P3 是低频或探索项。

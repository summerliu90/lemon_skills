# Analysis Assessment Rubric

本量表用于评审一份 Bug 分析是否可交付，不用于把 AI 的自然语言流畅度当作质量。

## 证据质量（0–5）

| 分数 | 判定 |
|---:|---|
| 0 | 没有当前案例证据，只有猜测 |
| 1 | 只有用户描述，没有可定位来源 |
| 2 | 有截图或单条日志，但缺少时间/环境 |
| 3 | 有多条可定位证据，时间和版本基本一致 |
| 4 | 有成功/失败对照、调用链或数据关联 |
| 5 | 证据可重放、可审计，并覆盖因果链关键节点 |

## 关联质量（0–5）

| 分数 | 判定 |
|---:|---|
| 0 | 只复述现象 |
| 1 | 只指出一个模块 |
| 2 | 连接页面、接口或服务中的两个节点 |
| 3 | 说明功能、业务规则和接口之间的关系 |
| 4 | 覆盖数据、状态、依赖和版本变更 |
| 5 | 每个关键关系都有来源证据和反例处理 |

## 假设质量（0–5）

| 分数 | 判定 |
|---:|---|
| 0 | 直接下结论，没有假设 |
| 1 | 只有一个没有依据的原因 |
| 2 | 有多个原因但没有区分优先级 |
| 3 | 每个原因有依据和验证方式 |
| 4 | 验证有预测、成本、停止条件和排除逻辑 |
| 5 | 假设状态随验证证据更新，能保留多根因或明确剩余不确定性 |

## 处置质量（0–5）

| 分数 | 判定 |
|---:|---|
| 0 | 没有修复和回归建议 |
| 1 | 只有“优化/加强监控”等空泛建议 |
| 2 | 有修复方向但没有风险或回滚 |
| 3 | 有止血、修复、回归三类建议 |
| 4 | 有发布门禁、监控阈值、数据安全和验收标准 |
| 5 | TestPilot 可执行验证，结果可回填，具备关闭条件和观察期 |

## 建议结论

- 18–20：可进入修复或发布评审。
- 14–17：可作为分析草案，需要负责人复核。
- 9–13：只能作为分诊材料。
- 0–8：退回补充证据，不得用于根因结论。

任何安全、数据损坏或生产 P0 风险，即使总分足够，也必须人工升级。

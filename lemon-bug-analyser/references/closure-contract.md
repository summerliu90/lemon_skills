# Closure and Regression Contract

## 为什么需要关闭契约

Bug 分析的结束不是“报告写完”，而是当前问题的处理证据已经足够，或者风险被明确接受。关闭契约防止分析在提出一个合理猜测后过早结束。

## 回归对象

每个修复至少建立以下对象：

```yaml
regression_id: REG-001
source_bug: TP-BUG-0001
root_cause_refs: [H-001]
trigger_case: "原始失败路径"
adjacent_cases: ["边界", "反向", "依赖失败"]
preconditions: []
actions: []
assertions: []
test_layer: api|ui|integration|data|performance|security
automation: candidate|manual|automated|not-suitable
owner: "string"
evidence_refs: []
```

## 需求映射

| 受影响对象 | 必须验证 |
|---|---|
| 页面/交互 | 操作成功、错误提示、状态恢复、重复点击 |
| API 契约 | 请求参数、状态码、响应 schema、超时和重试 |
| 业务规则 | 允许/禁止状态、权限、边界和例外 |
| 数据写入 | 事务、幂等、消息、最终一致和补偿 |
| 性能 | 基线、P95/P99、吞吐、资源和降级 |
| AI 输出 | 输入、上下文、模型、工具、格式和安全策略 |

## TestPilot 结果映射

TestPilot 回传时需要携带：

- `regression_id`
- 构建、环境、设备和数据夹具
- 执行时间和重试次数
- 每一步动作和断言结果
- 截图、日志、请求、Trace ID
- 失败原因是“产品失败、测试失败、环境阻塞还是数据阻塞”
- 与根因假设的关联

不能把“用例通过”自动解释成“根因已修复”；还要确认原始证据对应的现象消失，以及相邻风险没有新增。

## 关闭检查清单

- [ ] 原始失败已在相同条件下不再复现。
- [ ] 至少一个相邻边界已验证。
- [ ] 修复路径和根因假设一致。
- [ ] 没有新增错误、性能退化或数据异常。
- [ ] 必要的监控和告警已上线。
- [ ] 数据修复有计数、抽样和回滚记录。
- [ ] 生产问题完成观察期。
- [ ] 未完成事项有负责人和截止时间。

## 四态关闭结论

### Closed

根因确认、修复验证、回归和观察期全部通过。

### Closed with risk

问题已缓解，但存在已记录且被负责人接受的残余风险。

### Pending

当前有可行的下一步，但证据或回归尚未完成。

### Blocked

缺少外部权限、日志、环境或业务决策，且没有安全的替代验证路径。

## 观察期

观察期不应使用固定天数替代业务风险判断。至少考虑流量周期、批处理周期、支付/结算周期、缓存 TTL、消息重试窗口和数据对账窗口，并记录阈值和异常升级动作。

## 责任边界

分析工具负责结构化证据、提出验证和指出风险；测试负责人负责验收范围；开发负责人负责修复和技术风险；业务负责人负责规则确认；运维/平台负责人负责环境、发布和监控；数据负责人负责数据修复安全。

## 不可自动关闭的情况

- P0/P1 尚无当前验证证据。
- 任何受影响数据数量仍未知且风险可能扩大。
- 安全问题没有完成修复或风险接受。
- TestPilot 只执行了单一路径，没有原始失败条件。
- 历史案例被直接复用但没有当前差异审查。
- 回归通过但线上监控仍超过门槛。
